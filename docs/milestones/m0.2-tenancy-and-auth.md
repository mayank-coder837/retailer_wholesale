# M0.2 — Tenancy and auth (plan)

Goal: every request runs inside one tenant, enforced by PostgreSQL row-level security, and users sign up, log
in, refresh and switch tenant with rotating refresh tokens (ADRs 0002, 0007). Acceptance (roadmap): two tenants
seeded; neither can see the other's rows through any endpoint.

## Database

| Table | Scope | Notes |
| --- | --- | --- |
| `tenant` | RLS on `id` | name, status, default_locale |
| `business` | tenant | legal_name_en/_ar, trade_license_no, trn, vat_registered, base_currency, fiscal_year_start_month, time_zone, costing_method (`moving_average`), negative_stock_allowed |
| `branch` | tenant | business_id, code, name_en/_ar, address, **emirate (required, CHECK on the 7 emirates)**, is_head_office |
| `warehouse` | tenant | business_id, branch_id, code, name_en/_ar, is_default |
| `node` | tenant | kind (`branch_main_pc`, `cloud`), branch_id, name; sync cursors for M2.1 |
| `membership` | tenant | user_id, status (`invited`, `active`, `suspended`) |
| `user` | global | email (citext, unique), password_hash (argon2id), full_name, locale, failed_logins, locked_until, disabled_at |
| `refresh_token` | global | user_id, family_id, tenant_id/membership_id of the session, token_hash, client, expires_at, rotated_at, revoked_at |
| `sync_outbox` | tenant | node_id, seq, table_name, row_id, op, payload — filled by a trigger on every tenant table (ADR 0010) |

Every tenant table: `id` UUIDv7, `tenant_id`, `created_at/by`, `updated_at/by`, `origin_node_id` (defaults from
`app.node_id`), `ENABLE` + `FORCE ROW LEVEL SECURITY`, one policy on `app.tenant_id`, a sync-outbox trigger.
Helpers in `app/core/rls.py` make a migration do all of this in one call.

## Roles and tenant context

- Migrations run as the owner (superuser locally / a `BYPASSRLS` role in the cloud) and create the `NOLOGIN` role
  `smartbiz_app` with table privileges.
- The API connects with its login and immediately runs `SET ROLE smartbiz_app` on every new pooled connection, so
  RLS always applies — even when the login is a superuser in development. A test asserts `current_user`.
- Each request transaction runs `set_config('app.tenant_id' | 'app.user_id' | 'app.node_id', …, true)` from the
  verified access token. No context → `NULL` → zero rows.
- Pre-tenant lookups go through `SECURITY DEFINER` functions only: `auth_list_memberships(user_id)` and
  `auth_get_membership(membership_id)`.

## API

| Endpoint | Purpose |
| --- | --- |
| `POST /auth/signup` | user + tenant + business + head-office branch (emirate) + default warehouse + node + owner membership; returns tokens |
| `POST /auth/login` | email + password (+ `tenant_id` when the user has several); lockout after 5 failures for 15 min |
| `POST /auth/refresh` | rotates the refresh token; reuse of a rotated token revokes the whole family |
| `POST /auth/logout` | revokes the family |
| `POST /auth/switch-tenant` | new tokens for another membership of the same user |
| `GET /me` | user, current tenant, memberships |
| `GET/POST /businesses`, `GET /businesses/{id}` | tenant-scoped (permissions arrive in M0.3) |
| `GET/POST /businesses/{id}/branches`, `GET/POST /branches/{id}/warehouses` | tenant-scoped |

Tokens: access JWT (HS256, 15 min, claims `sub`, `tid`, `mid`, `nid`, `sid`); refresh token opaque 256-bit, stored
as SHA-256, 30 days. Web gets the refresh token in an `HttpOnly; SameSite=Strict` cookie on `/auth`; desktop
(`client: "desktop"`) gets it in the body and stores it with Electron `safeStorage`.

## Tests

- `assert_tenant_isolated` for every tenant table (read, update, delete, cross-tenant insert rejected).
- Catalogue check: every table with `tenant_id` (and `tenant`) has RLS enabled + forced, a policy, a sync trigger
  and an isolation factory; global tables are an explicit allow-list.
- No tenant context → 0 rows; the API connection runs as `smartbiz_app`.
- Auth: signup, login, wrong password, lockout, multi-tenant selection, refresh rotation, reuse revokes the
  family, logout, switch tenant, expired/forged tokens.
- Endpoint isolation: tenant B lists only its own businesses and gets 404 for tenant A's ids.
- Every write produces a `sync_outbox` row with the node id.
- Desktop: refresh-token store round-trip with an injected encryptor.

## Out of scope (later milestones)

Permissions and roles (M0.3); audit log, idempotency keys, numbering (M0.4); login screens (M0.5).
