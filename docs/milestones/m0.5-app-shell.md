# M0.5 — App shell (plan)

Goal: the real front door. A new user signs up through an onboarding wizard, lands on the dashboard, and moves
around a bilingual shell; returning users stay logged in. Acceptance (roadmap): a new user completes onboarding and
lands on the dashboard in either language, on web and desktop.

## Session (replaces the M0.3 in-memory login)

- Access token in memory, renewed ~1 minute before it expires through `POST /auth/refresh`.
- Refresh token: **web** — the HttpOnly cookie (requests use `credentials: "include"`; the API allows credentials
  for its configured origins); **desktop** — kept by the Electron main process with `safeStorage`
  (`window.smartbiz.session`).
- On start-up the app tries one silent refresh, so a returning user skips the login screen.
- Logout calls `POST /auth/logout` and forgets the token on both clients.

## Onboarding wizard (`/signup`)

Five steps, one screen each, validated before moving on, all strings in en/ar:

1. **Account** — your name, email, password, account (trade) name.
2. **Business** — legal name in English and Arabic, trade licence number.
3. **Head office** — branch name (en/ar), emirate (decides VAT 201 Box 1).
4. **VAT** — VAT-registered? TRN (15 digits, required when registered), base currency (AED default), fiscal year
   start month.
5. **Industry** — pick one of the five packs (or skip).

Submit = `POST /auth/signup` (everything except industry), then `POST /businesses/{id}/industry-packs`, then the
dashboard.

## Shell

- **Sidebar:** Dashboard, Sales, Purchases, Inventory, Accounts, Reports (Phase 1 placeholders), Settings → Roles.
  Logical CSS (start/end), so it flips correctly in Arabic.
- **Top bar:** business switcher (the tenant's businesses, remembered per user), account switcher (memberships →
  `POST /auth/switch-tenant`), language switch, user menu with logout.
- **Dashboard:** KPI cards from the concept — Sales today, Receivables, Outstanding after PDCs, Cheques due this week,
  Cash and bank, Low-stock items — showing "—" with "available in Phase 1".
- **Route guard:** signed-out users go to `/login`; `/` goes to the dashboard or login.
- **Desktop shortcuts** (Tally style, desktop app only, since F5 reloads a browser): F8 sales, F9 purchase,
  F5 payment, F6 receipt → their Phase 1 placeholder pages.

## Tests

- Vitest: wizard step validation and the exact signup + pack payloads; silent refresh on start (web cookie and
  desktop store); route guard; business and account switchers; shortcuts on desktop only; Arabic shell is RTL.
- Playwright against the **real API** (new CI job with PostgreSQL + the API): sign up through the wizard →
  dashboard, in English and in Arabic; reload keeps the session; logout returns to login.
