# M0.1 — Repo and tooling (plan)

Goal: an empty but complete monorepo where every later milestone only adds code — the API, SPA and desktop shell
start, CI runs lint/types/tests, and the product name comes from one config value.

## Deliverables

| Area | What | Path |
| --- | --- | --- |
| Config | `product.json` (`name: "SmartBiz OS"`, `slug`, `appId`), exported as `@smartbiz/config` | `packages/config/` |
| API | FastAPI app factory, settings (pydantic-settings; reads `product.json`), `/health` (liveness) and `/health/db` (readiness), RFC 7807 error handler skeleton, async SQLAlchemy engine, Alembic (async env, baseline), OpenAPI export script | `apps/api/` |
| SPA | Vite + React + TS, Tailwind v4, shadcn/ui (`Button`), TanStack Router + Query, react-i18next en/ar with `dir="rtl"` switch, runtime API URL (`config.json`, overridable by the desktop preload), product name from config | `apps/web/` |
| API client | `openapi.json` + generated types (`openapi-typescript`) and a typed fetch client (`openapi-fetch`) | `packages/api-client/` |
| Desktop | Electron main + preload (sandboxed), loads the SPA (Vite dev URL in dev, built files in prod), `window.smartbiz` bridge; electron-builder config reads `product.json` | `apps/desktop/` |
| Dev stack | Docker Compose: `db` (postgres:17, host port 5440), `api`, `web`; `cloud` profile adds `redis` (Celery worker and an S3-compatible service arrive with their code in M0.4; the `minio/minio` image is no longer published) | `infra/compose.yaml` |
| Commands | `make up / down / migrate / seed / test / lint / gen-client` + `make install`, `make e2e`, `make dev-api`, `make dev-web`, `make dev-desktop` | `Makefile` |
| Quality | ruff, mypy strict on `app/`, ESLint, Prettier, tsc; pre-commit; `.gitattributes` (LF) | root |
| CI | GitHub Actions: api (ruff, mypy, migrations, pytest with a postgres:17 service), web (prettier, eslint, tsc, vitest, desktop tests, build, playwright), client-drift check | `.github/workflows/ci.yml` |

## Tests

- API: `/health` returns status and the product name; `/health/db` reports the database (and a problem response
  when it is down); settings read `product.json`; OpenAPI export contains `/health`.
- Web (Vitest): app renders the product name from config; API status online/offline; language switch sets
  `dir="rtl"` and Arabic text.
- Web (Playwright): home renders in English and Arabic; the language choice survives a reload.
- Desktop (node:test): installer name and app id come from `product.json`; UI source and API URL resolution.

## Notes

- The Electron scaffold in the main checkout (root `package.json` with electron, electron-builder, supabase) is
  replaced by `apps/desktop` and the root workspace; the old untracked root files there should be deleted after
  merge. Supabase CLI is not a dependency until M2.1.
- Seed (`make seed`) is a placeholder until M0.2 creates the first tables.
- TypeScript is pinned to 5.9: typescript-eslint and openapi-typescript do not support 7.x yet.
