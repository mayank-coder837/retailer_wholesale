# 0007 — Authentication

Status: Accepted · 2026-10-10

## Decision
- Email + password, hashed with argon2id (`argon2-cffi`; rehash on login when parameters change).
- Access token: signed JWT, 15 minutes, claims `sub` (user), `tid` (tenant), `mid` (membership), `sid` (session).
- Refresh token: opaque random 256-bit value, stored hashed, 30-day sliding expiry, **rotated on every use**.
  Tokens form a family; reuse of an already-rotated token revokes the whole family (theft detection).
- Web: refresh token in an `HttpOnly; Secure; SameSite=Strict` cookie scoped to `/auth`.
  Desktop: refresh token kept by the Electron main process with `safeStorage` (Windows DPAPI), never in
  renderer JavaScript.
- Switching tenant issues a new access token for that membership. Permissions are resolved per request from
  role assignments (cached in Redis, invalidated on change).
- Rate limiting and lockout on login; email verification and password reset by signed, single-use links.
- Later: TOTP 2FA for Owner and Accountant roles. SSO is out of scope for Phase 1.

## Alternatives
Hosted identity (Auth0, Cognito) — rejected for now: per-user cost, UAE data-residency questions, and tenant
membership logic lives in our database anyway. Revisit if enterprise SSO is needed.
