# Roadmap — Phase 0, Phase 1 and cloud sync

SmartBiz OS is built local-first (ADR 0008): Phases 0–1 produce a desktop app that runs a branch fully offline on
its main PC, with office PCs on the LAN, and are piloted without any cloud server. Cloud sync, browser access and
multi-branch follow as M2.1. Each milestone stops for review with: what was built, how to run it, test results,
open questions. Updated 2026-10-11 for `decisions-round-1.md`.

**Before M0.1** (developer PC, decision T1): Docker Desktop with WSL 2, `make`, `uv`, `pnpm`, Python 3.12 —
installed and version-checked.

**Phase 0 gate:** `make up && make migrate && make seed` gives a working demo tenant; the installer gives the same
on a clean PC with a second PC on the LAN; all tests pass in CI; cross-tenant tests cover every table.

## Phase 1 — Trader MVP (local-only)

| Milestone | Scope | Acceptance criteria | Proving tests |
| --- | --- | --- | --- |
| **M1.1 UOM engine** | Unit families, units, standard conversions, product units, conversion at entry | Roll/meter and carton/piece conversions exact; lines store entered + base qty | Hypothesis: round-trip conversions lose nothing at 6 dp; factor > 0; rounding to unit decimals |
| **M1.2 Catalog** | Products, variants, attributes, barcodes (per unit), categories, brands, custom fields | Textile pack creates a fabric with colour/width variants and roll/meter units; barcode scan finds variant + unit | Custom-field validation tests; barcode uniqueness per tenant; isolation tests |
| **M1.3 Pricing engine + customer history** | **Last price to this customer first** (same unit, or converted and flagged), then customer list > group list > quantity break > promotion > base; min-price warning; **customer history panel** (all items supplied to the customer: date, invoice no., qty, unit, price, newest first, searchable, one-click add) | Engine returns price + `price_source`; the panel shows the customer's own history only | Table-driven tests for each priority level incl. unit-converted last price; history query tests (per customer, order, search); min-price warning |
| **M1.4 Parties + credit control** | Party with roles, addresses, TRN, customer/supplier profiles, credit limit/days, warn/block; PDCs in hand shown beside balance | Over-limit order warns or blocks per policy; override audited | Credit check tests (limit, overdue days, override, PDC not reducing balance) |
| **M1.5 Accounting core** | Chart of accounts (generic UAE trading), account roles, journal, vouchers (payment, receipt, contra, journal, expense, credit/debit note), bills + bill-wise allocation, fiscal years/periods + lock | Unbalanced entry impossible; locked period rejects posting without override | DB trigger test (unbalanced commit fails); Hypothesis: random balanced vouchers keep TB = 0; immutability tests |
| **M1.6 Inventory** | Stock ledger, one moving average across warehouses, batches/expiry, warehouse transfers, adjustments, cached balances, recost; **negative stock** (warning, costing at average/last purchase cost, revaluation on arrival to stock cost adjustment) + negative-stock report; **Item Transfer** document | Stock value = inventory account after any sequence of moves, including negative stock and item transfers | Hypothesis: random move sequences (incl. going negative) → ledger value = GL inventory; rule 27 example test; item-transfer value-equality test |
| **M1.7 Purchasing** | PO → goods receipt → bill, partial receipts, returns, price variance, posting; **Cancel and Reverse** for purchase documents | Three-step flow posts per rules 7–9; GRNI clears to zero; Cancel removes effects dated on the original date and frees the number; Reverse creates a dated debit note | Posting tests per rule; partial receipt tests; cancel/reverse tests (ledger, stock, VAT, payables, number reuse, audit snapshot) |
| **M1.8 Sales** | Quotation → order → delivery (no prices on print) → invoice (COGS via goods delivered not invoiced) → receipt, proforma, returns, credit checks, posting; **Cancel and Reverse** for sales documents and vouchers, with reuse warning when already sent | Full flow posts per rules 1–6; ageing correct; cancelled invoice disappears from every report and its number is reissued | Posting tests per rule; fulfilment-quantity tests; ageing buckets; cancel/reverse tests incl. allocations becoming advances and delivery notes returning to "not invoiced" |
| **M1.9 PDC register** | Received/issued cheques as **memo until cleared**; maturity calendar; deposit/clear/bounce/return; clearance creates the receipt/payment and settles intended invoices; statements show outstanding before/after PDCs in hand | No ledger entry until clearance; bounce changes only status | State-machine tests incl. illegal transitions; ledger untouched before clearance |
| **M1.10 VAT tax invoices** | Tax codes from the VAT 201 table, price modes (exclusive / inclusive / no VAT + reason), per-line VAT rounding, tax invoice vs simplified, en/ar HTML templates → PDF with line VAT and total VAT; VAT return draft (branch emirate split, drill-down) | Invoice PDF shows TRNs, Arabic, line and total VAT; Σ line VAT = total; VAT return draft drills down to documents | Rounding property test; template snapshot tests (en/ar); box mapping tests per tax code; credit-note period test |
| **M1.11 Reports** | Trial balance, P&L, balance sheet, AR/AP ageing (with PDC column), stock balance + valuation, negative stock, day book, party ledger | Reports read only from ledgers; TB balances | Report tests against hand-computed fixtures; shared semantic metrics |
| **M1.12 Import wizards** | Excel/Tally import of masters, opening balances, outstanding bills, stock; reconciliation report | Imported TB matches source; `opening_balance_equity` = 0 | Fixture imports (Excel, Tally XML); reconciliation tests; idempotent re-import |
| **M1.13 AI tool registry** | Typed tools with permission + risk tier, audit of every call, setup assistant, chat-to-voucher drafts (needs internet; queues or says "needs internet" offline) | "Received 5,000 cash from Ali Traders against INV-1093" → draft receipt, allocated, awaiting confirm | Tool permission tests; eval set (en/ar) with expected tool calls in CI; `via_ai` audit test |

**Phase 1 gate (automated end to end, offline):** a demo trader buys fabric by the roll, sells it by the meter on
credit, receives a PDC, deposits and clears it — and at the end the trial balance balances, stock value equals
the inventory account, and the customer's ledger shows zero outstanding.
